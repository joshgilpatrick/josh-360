Jira ticket pipeline, with completion review and PR cycle

Part 1: ticket to verified build

Part 2: completion review, PR, code review

The reviewer can only cite the plan

  • Every defect names a criterion in the spec and quotes it.
  • A script deletes any defect whose quote is not in the spec. The builder never sees it.
  • The spec's definition of done covers placeholders, partial work, weak tests and unrun checks.

Labels follow /pr-agent-review

  • Only scripts set a review label. No model does.
  • needs-agent-audit, audit-in-progress, then changes-requested, audit-blocked or the pass label.
  • 4 or more issues in a fix round re-queue the audit. Fewer set the pass label.

Left out on purpose

  • Plan gap goes back to Design.
  • Blocked audit opens a gate: re-run or stop.
  • The pipeline never merges. Your verdict labels start a new round.
