**Goal:** Build the ledger JP-99 designed: the database on the laptop, a recorder that writes every session's facts with no model and no help from Josh, the read command agents use, daily backups, and a one-time backfill from the history already on the laptop (JP-107).

**Architecture:** `ledger/db.py` opens `~/.josh-360/state/ledger.db` and applies `ledger/schema.sql` plus numbered migrations. Two small hooks append one JSON line per session event to a spool. A job, `ledger-record`, reads the spool, the transcript's metadata, git and the cost ledger (read-only), and writes sessions, episodes, refs, links, homes, costs and STATE.md notes. Every input from outside (Jira, git, the clock, the cost ledger, the file system root) reaches the code through injected arguments, so every test runs in the cloud on made-up data.

**Tech Stack:** Python 3.9, standard library only (`sqlite3`, `json`, `subprocess`, `gzip`), because it runs on the laptop's `/usr/bin/python3`. Tests use stdlib `unittest` under `tests/`, run by `python3 scripts/check.py`.

**Spec:** `docs/design/data-model.md` (JP-99), with `ledger/schema.sql`, `ledger/codes.json` and `tests/test_ledger_schema.py`. Ticket: JP-107. Read the spec first; this plan does not repeat it.

**Amended by JP-148 (17 November 2026)** with the five fixes from the JP-146 review, before any of it is built: the session row is written at session start (A1: Task 3, Task 5, the new `ledger/sessions.py`), the stricter patient-data rule (A2: Global Constraints, Tasks 2, 4, 5, 6 and 8), replacing a withdrawn row (A3: Task 2), the starter read from `codes.json` (A4: Task 3), and precedent by category (A5: Task 7). The schema and its tests already carry these; this plan builds the code that writes through them.

## Global Constraints

- Python 3.9 and the standard library only for every file under `ledger/` and `hooks/`. `from __future__ import annotations` at the top of each module that uses `list[str]` or `X | None`.
- Every connection is opened by `ledger.db.connect`, which sets `foreign_keys = ON`, `recursive_triggers = ON`, `journal_mode = WAL` and `busy_timeout = 5000`. No other code calls `sqlite3.connect` on `ledger.db`.
- Insert only. Never `UPDATE`, `DELETE` or `INSERT OR REPLACE` on `ledger.db`; `INSERT OR IGNORE` is allowed where a `UNIQUE` makes a repeat harmless. The only exception is `ledger/redact.py` (Task 8).
- Five tables are versioned: `session_episodes`, `session_summaries`, `debriefs`, `step_results`, `run_ends`. A first write is version 1; a replacement of a withdrawn row is `ledger.correct.next_version(...)` (Task 2), never a hand-counted number. Every read goes through the `current_*` views and `live_corrections`, never the raw tables.
- The `sessions` row exists before anything else about the session: the recorder writes it from the `SessionStart` spool line, and every writer that meets a session with no row calls `ledger.sessions.ensure` first (Task 5).
- Times are UTC, written `YYYY-MM-DDTHH:MM:SSZ`. Every row's `recorded_by` is the writing script's path from the repo root, for example `ledger/record.py`.
- `session_uid` is `<machine_id>:<tool>:<tool_session_id>`; `machine_id` is `m-` plus 8 random hex digits, made once.
- No transcript text, message text, command output or file contents is written anywhere: not the database, not the spool, not logs, not test fixtures. The recorder reads only these transcript fields: `type`, `subtype`, `sessionId`, `cwd`, `gitBranch`, `timestamp`, `uuid`, `isSidechain`, `customTitle`, `aiTitle`, `agentName`, `prUrl`, `prRepository`, `relocatedCwd`, `worktreeSession.worktreePath`, `toolUseResult.filePath`, `toolUseResult.type`. It never reads `message.content` text.
- The twelve free-text columns (spec, "Patient data") go through `ledger.text.short_text` before every insert.
- **No words of the session's own where patient data may be** (spec, "Patient data", rule 3). A session whose current home has `patient_data = 1` (a flagged system, an unknown system, or Unassigned), or whose folder is inside a folder named `.phi`, stores no title (`title` empty, `title_source` `withheld`), no STATE.md notes and no first line. The recorder works out the home before it writes the episode. One function decides this, `ledger.homes.keeps_words(home: dict, folder: str | None) -> bool`, and every writer of session text calls it.
- No backup leaves the laptop. The Azure upload is held (spec, "Storage"); nothing in this plan uploads.
- Gone quiet: the `SessionEnd` hook fired, or the transcript has not grown for 30 minutes (`QUIET_AFTER_SECONDS = 1800`).
- No model call anywhere in this plan. A test asserts the recorder imports no HTTP client and makes no network call except the Jira read (Task 4).
- Codes for `session_facts` come from `ledger/codes.json`; this plan writes only `compactions`.
- Laptop paths come from `laptop/common.py` (`state_dir()`, `logs_dir()`, `home()`). The cost ledger is `~/.claude/cost-ledger/ledger.db`, opened read-only with a `file:...?mode=ro` URI. Atlas's database is `~/.claude/atlas/atlas.db`, also read-only.
- A new background job is an entry in `jobs.yaml`; a new hook is an executable file in `hooks/<Event>/`; a new install step goes in `STEPS` in `laptop/install.py` (`AGENTS.md`, Commands).
- Tests and fixtures use made-up sessions only: ids like `sess-0001`, folders under a temp directory, tickets `JP-900` to `JP-999`.

## Review Focus

1. **A replace that slips past the triggers.** Any writer using `INSERT OR REPLACE`, or a connection opened without `recursive_triggers`, silently deletes a row. Test in Task 1 (`test_connect_refuses_insert_or_replace`).
2. **A transcript line that is not what it seems.** A malformed JSON line, a line over 1 MB, a truncated last line while the session is still writing, or a `cwd` that is not absolute must be skipped, not crash the pass or stop other sessions being recorded. Tests in Task 5.
3. **The same session seen twice.** The recorder runs every five minutes, and a session can be seen quiet, resumed and quiet again. A second pass over an unchanged session adds no rows; a resume adds episode 2 and leaves episode 1's rows alone. Tests in Task 5 and Task 6.
4. **Jira down.** A failed or slow Jira read must still record the session, with `jira_read = failed`, and be retried on a later pass, never written as Unassigned. Test in Task 4.
5. **Text that should not be there.** A title or STATE.md note that is too long, has a line break, or looks like patient data (the shared scan flags it) is cut or withheld, never refused by the database's `CHECK` and never dropped with the whole session. Tests in Task 2 and Task 6.
6. **Words under a flagged system.** A title, note or first line from a session whose home is flagged, unknown or Unassigned must never be written, even when the scan passes it: the scan cannot see a name typed fresh. Tests in Task 4, Task 5 and Task 6.
7. **A row about a session that has no row yet.** Anything written while the session runs (walker steps, asks, ticket links) needs the `sessions` row first, or the foreign key refuses it. Tests in Task 5.
