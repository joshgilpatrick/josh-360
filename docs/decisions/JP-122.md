# JP-122 decisions

| Date | Ticket | Question | Option taken | How to undo |
| --- | --- | --- | --- | --- |
| 2026-11-17 | JP-122 | Which session signed off a ticket, when gates never see their own session id? | The ledger's record of the `sign_off` step in the run (`step_results.session_uid`), read by `check-sign-off` and `mark-ready`. A signing session that is not on record is `invalid` and never ready, so "the author never signs" cannot pass by omission. | Have the agent report its own session id. |
| 2026-11-17 | JP-122 | How does an entry gate learn which graph it admits a run to? | The walker sets `JOSH360_GRAPH` for the entry gate (one line in `cmd_start`). The shared `ready` gate for the development and non-development graphs reads it, and a test or hand run may give `GRAPH_INPUT_GRAPH` instead. | Write one `ready` script per graph. |
| 2026-11-17 | JP-122 | How is the "third return goes to Josh" count kept between runs? | From the ticket itself: the number of "Returned to triage" comments, plus the route record's `returns` and `returns_seen` (comments seen when it was written). Josh's `ask_returned` answer in a run resets it. `returned_from` is the id of the newest new return note, because `return-to-triage` records no run id. | A counter in the ledger. |
| 2026-11-17 | JP-122 | What does `ask_josh` need so the ticket carries the question? | A new `post-question` gate between `revise` and `ask_josh` writes the spec's question comment once. The drafter's `needs_josh` result carries `question`, `recommendation` and `reason`. | Let the walker's ask card be the only place the question lives. |
| 2026-11-17 | JP-122 | How are "two drafter rounds, then Josh" kept exact when the engine takes a loop arrow after the gate has run? | `triage-verdict` counts this run's round notes and returns `exhausted` at two (three after one "one more round", and so on), and `ask_at_limit` is reached from that outcome as well as from loop limits. The drafter never runs a third time, and the check after round two still happens. | Cap the `apply_revision` arrow at one loop, which would ask Josh before checking the second round. |
| 2026-11-17 | JP-122 | How does a ticket's description get read, so a heading cannot be mistaken for a section? | Strictly: a section opens only on a bold label with its colon at the start of a line outside a code block (`lib/triage/ticket.py`), on text from `adf.to_marked`, which keeps bold labels and Gherkin fences. A heading, a plain label, a table or a panel opens nothing, so the section reads as missing instead of being guessed. | Reuse the looser `ticket_text.parse_sections`. |
| 2026-11-17 | JP-122 | Is a revision a new action in the ticket proposal contract? | Yes: `action: revise`, one ticket with its `key`, `closes` (gap numbers) and `authors`, or `needs_josh`. Ticket creation still refuses it. `apply-revision` rewrites the description in place, merges the authors, and comments the round; it never edits a ticket an allowed account did not create. | A separate contract file. |
| 2026-11-17 | JP-122 | How does triage keep from starting itself on its own comment (rule 11)? | The entry gate refuses when the newest comment begins `Triage: ` and is newer than the description's last edit. Any later edit by the author starts a run. | Mark runs with a label. |
| 2026-11-17 | JP-122 | Does `ready` check the sprint? | No. Whether a Ready ticket starts now or when Josh queues it is the runner's rule (JP-117). The Ready comment only says which, from the ticket's sprint field. | Check the sprint in the gate. |
| 2026-11-17 | JP-122 | Can a Task name Repository `none`? | Yes: C3 no longer treats `none` in Repository as an empty answer, because C7 and the routing table rule on it (a Story or a Bug with `none` fails S1 or B2). | Keep `none` out of Repository and use a different word. |
| 2026-11-17 | JP-122 | What stops the exit gate? | Nothing new: `no-loose-ends` is still JP-109's stub, so a run that reaches its end stops there, with the ticket already Ready. The tests assert exactly that. | Stub the exit gate in the tests. |
