| 2026-11-17 | JP-150 | How does the laptop sign in to Azure with no stored secret? | The Azure CLI as Josh: `az storage blob ... --auth-mode login`, after Josh runs `az login` once. The code needs no Azure library (the laptop code is standard library only), accepts no key, SAS token or connection string (the settings file refuses any other key, and the `AZURE_STORAGE_*` variables are removed from every call), and needs Josh to hold a Storage Blob Data Contributor role on the container. | Use a managed identity or a service principal if the upload ever runs off the laptop. |
| 2026-11-17 | JP-150 | Which account and container? | Not guessed. They are settings (`~/.josh-360/state/azure-backup.json` or `JOSH360_AZURE_ACCOUNT` and `JOSH360_AZURE_CONTAINER`). Until Josh sets them the job reports `not-configured` and uploads nothing. | Commit the two names to the repository if Josh prefers; neither is a secret. |
| 2026-11-17 | JP-150 | Part of `ledger-backup` or a job of its own? | A job of its own, `ledger-upload` (daily, 30-minute limit, report on `laptop-status`), so an Azure outage or an expired sign-in never fails or delays the local backup. It exits 0 on a failed upload so the runner still publishes the report saying `failed`; a failure is retried at the next daily run, and it catches up every missing copy then. | Call `upload.py` from the end of `backup.py`. |
| 2026-11-17 | JP-150 | What is "the same retention" in the container? | The laptop's rule, shared code: `backup.keep_names` (newest 14 daily, newest of each of the last 8 weeks). Container blobs named `ledger-<date>.db.gz` outside it are deleted; any other blob is never touched. | Keep every uploaded copy and remove only by hand. |
| 2026-11-17 | JP-150 | How does a redaction reach the uploaded copies? | `redact.py` downloads each uploaded copy, overwrites the cell the same way as the local copies, and uploads it back, so a copy with no local twin is covered. A container that cannot be reached, or a copy that cannot be read, leaves the cell's location in `state/azure-redactions-pending.json` (never its text) and `redact.py` exits 3; the next upload run does it first and reports `failed` while a copy is unreadable. | Delete a copy that cannot be read (a permanent deletion, so Josh's call). |
