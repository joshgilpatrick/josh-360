# JP-157 decisions

| Date | Ticket | Question | Option taken | How to undo |
| --- | --- | --- | --- | --- |
| 2026-11-17 | JP-157 | Does `mv` count as a deletion for the removal guard? | Yes (the review's recommendation). Renaming or moving a worktree strands another session as much as deleting it does, so `mv` is a deleting word and a marker that makes a command relevant to the guard. | Remove `mv` from `DELETING_WORD_RE` and `MARKER_RE` in `apps/session-atlas/hooks/atlas-removal-guard.js`. |
| 2026-11-17 | JP-157 | Which words open the deletion gate, after which the unchanged path, anchor and checkout-count rules run? | `rm`, `rmdir`, `unlink`, `shred`, `trash`, `srm`, `rimraf`, `rmtree`, `-delete`, `-exec`, `git clean`, `remove`, `prune`, `rename`, `move`, `mv`, plus the code spellings `rmSync`, `removeSync`, `os.remove`, `shutil.move`. Also a computed command name (`$x`, `${c}m`, `$'\x72m'`) as the command or just after a wrapper, and a shell, `eval`, `exec` or `source` as the command. Matching more words than strictly needed is safe: it only sends the command to the old rules. | Narrow or widen `DELETING_WORD_RE` and `RUNS_ARBITRARY_RE` in the guard. |
| 2026-11-17 | JP-157 | When is quoted text read as code? | Only when the command that owns the quote runs it. Data owners: `echo`, `printf`, the read-only verbs (`ls`, `cat`, `grep`, ...), `git` with a non-executing subcommand (commit, tag, log, show, merge, stash, ...), `gh` with api, pr, issue and similar, and an interpreter (`python3`, `node`, `ruby`, `perl`, `php`, `deno`, `bun`) with no `-c`, `-e`, `-p`, `-r` or `--eval` before the quote. Everything else, a quote that starts a command and an unknown program included, is an executor, so the guard still fails closed. A double-quoted `$( )` or backtick is always code. | Make `quotedIsData` in the guard return `false`; every quote is read as code again, as before JP-157. |
| 2026-11-17 | JP-157 | Is data text read as code when its command's output goes to a pipe, a redirection or a substitution? | Yes. `echo "rm -rf wt" \| sh` and `echo "..." > script.sh` can end in a run, so they keep the old behaviour. Cost: `echo "remove the worktree" > notes.txt` is still blocked, and the new block message names the command that matched. | Skip the pipe, redirect and substitution check in `end()` inside `lexSegments`. |
| 2026-11-17 | JP-157 | A program that is given a worktree path but has no deleting word (`python3 cleanup.py <worktree>`) used to be blocked by the path rule. | Allowed now, as the review's gate specifies. The guard cannot see what the program does, and the header already lists "deletion through a program that names no path in the command" as a known limit. A shell, `eval`, `exec` and `source` stay blocked because they run text the guard cannot read. | Open the gate for every interpreter that is given a path (`RUNS_ARBITRARY_RE`); this brings back the false blocks. |
